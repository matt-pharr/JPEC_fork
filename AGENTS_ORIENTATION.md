# AGENTS_ORIENTATION — RDCON → Julia conversion

## Purpose
This document is the primary orientation for AI agents working on the RDCON Galerkin/FEM conversion in the JPEC repository. It summarizes the project, where to look for code, how to run references/tests, and which PR instruction files to follow. See [CLAUDE.md](CLAUDE.md) for specific guidance on running code in this repository.

## Project summary
JPEC is a Julia conversion of the GPEC suite. The DCON module implements ideal MHD stability analysis using the classic ODE-based DCON path. RDCON is a Fortran fork that replaces the ODE integrator with a Galerkin/FEM outer-region solver. The conversion project ports the RDCON Galerkin path into Julia while preserving output parity with the Fortran implementation.

Key facts:
- The current Julia implementation mirrors the DCON ODE workflow in src/DCON.
- The RDCON Galerkin solver exists only in Fortran under src/DCON/rdcon_fortran/rdcon.
- The conversion is staged across PRs; each PR adds a well-scoped component and includes Fortran-vs-Julia reference tests.

## How to work on a PR
1) Read the relevant PR file completely.
2) Identify the Fortran subroutines listed for conversion.
3) Locate the corresponding Fortran source in src/DCON/rdcon_fortran/rdcon.
4) Implement Julia code under src/DCON (or a new Galerkin submodule when introduced).
5) Add unit tests that compare Julia outputs to Fortran reference fixtures.
6) Add or update integration tests for end-to-end parity.

## Testing and reference outputs
- The Fortran RDCON reference runner and fixtures are defined in PR1.
- Tests should always compare Julia outputs to stored reference fixtures generated by Fortran RDCON.
- Use the comparison helpers defined in PR1 to ensure consistent tolerances and reporting.

## Conventions and expectations
- Preserve numerical parity with Fortran first; optimize later.
- Avoid reformatting unrelated files.
- Keep new Julia APIs minimal and stable across PRs.
- Use deterministic outputs for tests (consistent ordering, stable formatting).

## Where to start
If you are new to the project, start with PR1 and then follow PR2 onward in order. Each PR file begins with a summary of what previous PRs already provide.
